## 영상별 관찰

### V1 — 턴·페이즈와 카드 효과 설명

- 초반 전장 위 중앙을 가로지르는 `TURN CHANGE` 배너가 나타났다가 사라진다. 이어 `STANDBY PHASE`, `MAIN PHASE 1` 배너로 현재 진행 상태를 짧게 알린다.
- 위쪽은 상대, 아래쪽은 자신의 영역이며 손패가 전장 가장자리에 배치된다. 배너가 사라진 뒤 전장 전체가 다시 보인다.
- 공개 카드가 전장 중앙 쪽으로 확대되고, 하단의 가로형 설명 패널에는 카드 썸네일·카드명·종류·효과 텍스트가 표시된다. 설명 패널은 전장 일부를 덮고 이후 사라진다.
- 후반에는 Life 피해 수치와 강한 타격 연출이 나타난다.
- 이 패널이 **hover로 열린 것인지, 효과 처리로 자동 표시된 것인지**는 해당 프레임만으로 확정하지 않는다. 입력 차단 여부와 서버 처리 시점도 알 수 없다.

### V2 — 상세 패널·기록·효과·공격

- 좌측에는 선택 카드의 그림·수치·설명, 우측에는 카드 이미지가 포함된 세로 기록 패널이 보인다.
- 효과 처리 중 관련 카드가 발광하거나 확대되고, 필드 수치가 바뀌며 화면이 잠시 어두워지는 구간이 있다.
- `BATTLE PHASE` 중앙 배너 이후 공격과 Life 피해 피드백이 이어진다.
- 기록 패널이 보이는 것은 확인했지만, **어떤 버튼으로 여는지, 왼쪽/오른쪽 슬라이드 방식인지, 최신 항목 방향과 자동 스크롤 정책**은 이 영상으로 확정할 수 없다.

### V3 — 연속 카드 처리와 페이즈 안내

- 짧은 구간에 여러 카드가 이동·발광한다. 상하 플레이어의 전장과 하단 손패가 유지된다.
- 마지막 부분에 `MAIN PHASE 1` 배너가 나타난다.
- 카드가 이동한다는 사실은 확인되지만 모든 이동의 시작 Zone과 원인을 식별하기 어렵다. 이 영상을 **명확한 덱→손패 드로우 증거**라고 보고하지 않는다.

### V4 — 후보 카드 선택창

- 카드가 빛난 뒤 전장 앞에 별도의 후보 카드 창이 나타난다. 상단 안내는 손으로 되돌릴 카드 선택을 요구한다.
- 후보 중 선택한 카드에 선택 표시가 붙고, `선택`/`결정` 버튼 상태가 바뀐다. 결정 후 창이 사라진다.
- 이는 효과별 후보 선택창의 실제 사례다. Project C에 같은 카드 효과·후보 규칙·확정 방식이 존재한다는 뜻은 아니다. 클릭 방식, 선택 피드백, 완료 후 닫힘이라는 상호작용만 참고할 수 있다.

### V5 — 소환 선택과 정착 연출

- 초반 `Select position` 안내와 필드 영역 강조가 보인다.
- 이후 카드 확대, 회전/합성, 빛, 큰 몬스터 표현, 카드명·능력치 표시를 거쳐 카드가 필드에 정착한다.
- 이 클립에서 손패를 집어 필드로 끌어 놓는 **전체 포인터 드래그 경로가 명확하게 보인다고 단정하지 않는다**. 드래그 소환 요구는 PDF의 사양으로 분류한다.
- 레퍼런스의 위치 선택은 Project C에 도입하지 않는다. 사용자가 필드 순서 자동 배치를 명시했다. 소환 재료·합성·수치 체계 역시 복제하지 않는다.

## 구현 수치로 제안할 수 있는 값

다음 값은 영상에서 정밀 측정한 수치가 아니라 PDF 및 일반적인 가독성을 바탕으로 한 **초기 조정값**이다. Astra가 실제 화면을 보며 조정해야 한다.

- 턴 안내: fade-in 0.2초, hold 0.7초, fade-out 0.3초. 화면 dim 정도와 게임 입력 차단 여부는 별도로 결정한다.
- hover 정보: 약 0.2초 지연. 선택 고정과 hover를 구분하고, 상세 패널은 화면 안으로 제한한다.
- 드로우: 카드당 약 0.4초. 자신의 카드만 공개된 데이터로 앞면을 보여주고 상대는 뒷면 유지.
- 소환/효과 팝업: 약 1.5초, 순차 표시. 게임 상태 적용과 별개인 표현 큐로 둔다.
- Battle Log: 약 0.25초 왼쪽 slide. 닫힌 패널과 화살표/드래그 시각 요소는 raycast를 막지 않는다.
