# 전투 UI 시각 비교와 구현 가이드 — 1920×1080

## 비교 범위와 읽는 법

- 레퍼런스: 사용자 제공 `확장 자원 트레이의 달빛 카드 배틀.png`, 1671×941. 아래 수치는 이미지를 1920×1080에 맞춰 환산한 **눈대중 추정값**이다. 곡선, 발광, 회전 때문에 경계는 대략 ±10~20px 오차가 있다. Glow를 뺀 눈에 보이는 프레임의 외곽을 우선 측정했다.
- 현재 화면: `Artifacts/MoonlitArena/1920x1080.png`. Unity BattleScene에 테스트 스냅샷을 주입한 화면으로, 양 필드 5장·손패 5장의 **축소 상태**다. 실제 온라인 경기나 펼친 손패의 대표 화면은 아니다. 아래 현재 크기는 이 스크린샷의 추정 외곽이다. 확대 상태는 별도 캡처해 비교해야 한다.
- 좌표: **화면 왼쪽 위 (0,0), 오른쪽 아래 (1920,1080)**, 단위 px. 표의 x/y는 좌상단, w/h는 가로/세로다. Unity의 중앙 앵커 RectTransform으로 옮길 때 중심점은 `(x + w/2 - 960, 540 - y - h/2)`다. 회전 카드의 w/h는 회전 전 몸체 크기와 회전 후 점유 범위를 구분한다.
- 레퍼런스의 3장 필드, 5종 자원, 카드 이름과 숫자는 예시다. 실제 서버 상태·공개 범위·입력 허가가 기준이다. 새 배경에 금색 장식이 이미 있으므로 기존 `ArenaGuides`는 꺼진 상태를 유지하고, 구획선은 카드 가독성 확인 뒤 필요한 경우에만 추가한다.
- PDF `Executive Summary.pdf`의 문제 목록은 참고했다. 다만 권장안의 **가로 4:3 필드 카드, 가로 2:1 턴 버튼, 지름 100~120px 영웅**은 첨부 레퍼런스와 맞지 않아 적용하지 않는다. Canvas Scaler도 이미 Scale With Screen Size, 1920×1080, Match Width(0)다. 손패가 작은 직접적 요인으로는 현재 `BattleVisualSettings.asset`의 축소 배율 0.513이 확인된다. Scaler 고장이라고 단정할 근거는 없다.

### 배치 계산과 한계

- 필드의 5장 중심 간격 212px은 180px 몸체와 32px 여백이다. 1~5장은 중심 정렬하며 3장일 때 중심 x 748/960/1172로 레퍼런스의 세 카드 간격에 근접한다. 현 구현의 180×228 프리팹 비율은 0.789이고 참조 외곽 추정은 약 0.84다. 프레임/배지의 실제 투명 영역을 분리해 측정한 뒤 프리팹은 레퍼런스 실루엣에 맞게 조정하고, 일러스트를 비균일하게 늘리지 않는다.
- 서버 기본 데이터의 `FieldLimit`은 5이고 허용 범위는 1~32다. `BattlePresenter`는 스냅샷의 `FieldLimit`을 사용한다. 6~10장은 기존 `CardTableLayout`처럼 영역에 맞춰 축소하되, 10장은 대략 90~100×115~127px 수준으로 작아질 수 있다. 해당 상태에서 이름과 숫자가 읽히지 않으면 기존 Hover/상세 정보로 원문을 제공한다. 11~32장은 단순 축소만으로는 가독성을 보장할 수 없다. 필드 페이지 또는 수평 스크롤을 별도 작업으로 설계하고 양 진영과 공격·효과 대상 전체에 접근 가능하게 검증한다. 필드 한도를 5나 10으로 고정하지 않는다.
- 손패는 카드 그림의 겹침을 허용하되 프레임과 비용 배지의 읽을 부분을 확보한다. 순서, 드로우 도착점, Hover 시 형제 순서, 클릭 영역을 함께 시험한다. 선택 카드 목표 박스는 약 x500~1500, y740~1065 안에서 화면·자원 패널을 피해 clamp한다. 확대가 필드 카드의 조작 영역을 가릴 경우 확대 카드를 일시적으로 측면 상세 패널에 표시하는 방식을 검토한다. 이를 확정하기 전 1/5/10장과 선택 상태를 캡처한다.
- 1920×1080에서 이 좌표를 먼저 확정한다. 현재 Canvas Scaler는 화면 폭을 기준으로 스케일한다. 다른 화면 비율에서는 안전 영역, 앵커와 배경 중앙 크롭을 따로 검증하고 좌표를 그대로 픽셀 고정하지 않는다.

## 텍스트와 아이콘

레퍼런스는 크림색 큰 숫자와 어두운 외곽선, 금속 배지의 명확한 바탕으로 위계를 만든다. 현재 화면은 손패 전체 축소로 이름과 수치가 읽기 어려우며, 턴 버튼 글자는 어두운 투명 배경에 놓여 대비가 약하고, 전투 기록·메뉴는 시스템 UI처럼 보인다. 필드 이름은 밝은 일러스트 위에 작은 회색 글자로 겹쳐 묻힌다. 현재 프리팹은 `NotoSansKR-Regular` TMP 에셋을 사용하며 수치가 크더라도 부모 배율에 따라 최종 표시 크기가 줄어든다. TMP의 입력 크기와 실제 화면에서의 글자 높이는 동일한 픽셀이 아니므로 Game View를 기준으로 확인한다.

프로젝트의 Noto Sans KR Medium/Bold 원본을 TMP 폰트 에셋으로 준비해 한국어와 숫자를 공통으로 쓴다. 장식적인 제목용 글꼴은 한글 지원·라이선스 확인 후 선택하고, 미지원 글리프는 Noto로 대체한다. 외곽선은 TMP 머티리얼 프리셋으로 적용하되 전역 공유 머티리얼의 다른 UI를 함께 바꾸지 않는다. 배지/띠 배경의 실효 색과 글자색 대비는 실제 합성 결과로 측정해 일반 텍스트 4.5:1을 목표로 하고, 가장자리/그림자는 보조 수단으로 사용한다. 긴 이름·현지화·다자리 수치, 확대/축소 상태를 함께 점검한다.

## Codex 구현 순서와 완료 판정

1. **기준 캡처와 레이아웃 고정.** 현 Scene의 축소/펼친 손패를 1·5·10장, 필드 1·3·5·10장으로 1920×1080에서 저장한다. 스냅샷은 테스트 전용이며 각 화면에 카드 수·상태를 기록한다. 레퍼런스를 같은 크기로 맞춘 비교 이미지를 만들고, 실루엣과 실제 Sprite 불투명 경계를 재측정한다. 기존 3D 프리팹과 배경은 유지한다. 완료: 목표 좌표와 실제 겹침을 캡처로 승인 가능하게 비교.
2. **손패/필드 프리팹의 형태와 크기.** `BattleCard.prefab`과 `BattleFieldCard.prefab`의 분리를 유지하고 공통 `CardWidget`/서버 데이터 연결을 재사용한다. 두 프레임과 배지 아트를 교체하고 `CardTableLayout`의 크기·간격·부채꼴과 선택 경계만 조정한다. 기존 오른쪽→손패 드로우 경로, 순서, 클릭/Hover, 선택 및 필드 대상 선택을 검증한다. 완료: 1/5/10장, 선택·드로우 전후 캡처 및 UI hit test 통과. 기본 5장 필드는 레퍼런스 크기를 유지한다.
3. **영웅·턴·자원·존 배치와 공통 아트.** `BattleScreen.prefab`의 RectTransform, 영웅 프레임·HP, 턴/페이즈, 존, 기존 요력과 기록/메뉴를 위 목표대로 옮긴다. HP와 요력은 서버 상태 연결 그대로, 상대 덱은 비공개를 유지한다. 활성/비활성·대기·선택 가능·Hover를 검증한다. 완료: 각 버튼 개별 Raycast, 실제 수치 갱신, 손패·필드와의 충돌 검사.
4. **폰트와 가독성.** TMP Medium/Bold 에셋 및 머티리얼 프리셋, 이름 띠, 수치 크기·외곽선·그림자 정리. 긴 한글 이름과 다자리 숫자, 배경 위 대비와 확대/축소 상태를 검증한다. 완료: 캡처에서 정보가 읽히고 잘림이나 불필요한 말줄임이 없다.
5. **정적 금속과 상태 효과.** 프레임별 마스크를 새 실루엣에 맞추고 기존 UI 셰이더의 스텐실/마스크/CanvasGroup 호환을 유지한다. 상태별 광택 강도를 입력 허가 상태에 연결하고 버튼과 카드가 모두 빛나지 않게 한다. 완료: 정지/선택/대기 캡처, 저사양 성능 및 타깃 플랫폼 셰이더 확인.
6. **통합 회귀와 화면 비율.** 1920×1080에서 먼저 실제 플레이 확인 후 2560×1440, 1920×1200, 2520×1080을 확인한다. 손패 0/1/5/10, 필드 1/3/5/10 및 큰 FieldLimit, 드로우·사용·소환·공격·선택형 효과·턴 변경·ModalBlocker·서버 스냅샷·재접속·경기 종료를 기존 테스트와 실제 입력으로 확인한다. PDF 및 Stage2/3 문서에 기록된 이전 실패는 기존 실패와 신규 회귀를 구분하고 원인을 재현한다. 완료: 캡처, 실행한 테스트, 실패/미검증 사유를 기록한다.
